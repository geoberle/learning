Lesson 01 · About 5 minutes

From prompt to first token—and beyond

Trace one request through the two phases of LLM inference: prefill and decode.

The minimum vocabulary

Inference means running a trained model on input. A tokenizer turns the input text—the prompt—into numbered units called tokens. A token may represent a word, part of a word, or punctuation. Tokenization source.

The model predicts probabilities for the next token; a selection rule chooses one. Append that token and repeat, using the prompt plus the generated tokens so far as context. Stop at an end token or another limit. Generation source.

One request, two phases

We’ll use ordinary generation with a KV cache, without prompt-cache reuse or speculative decoding.

Prefill: the model processes the prompt [The][ cat] and stores reusable intermediate results. It also computes scores for tokens that could come after the last prompt token, [ cat]. A selection rule uses those scores to choose the first generated token—for example, [ sat]. Prefill therefore supplies the prediction used to start the answer.

Decode: the model now processes the selected [ sat], reusing stored work from [The][ cat]. It computes new scores for what comes next, from which we select [ down]. Each further decode step processes the latest selected token to predict another. Phase source: AWS.

The KV cache stores intermediate attention results, not a prewritten answer. For now, treat it as reusable work from processed positions; attention and the meaning of “keys” and “values” come next. Cache source.

All prompt tokens are known in advance, so prefill can work across their positions in parallel. Future output tokens depend on earlier choices, so ordinary decode advances sequentially. Processing only the latest token does not mean ignoring earlier context: cached state carries it forward.

Why the first wait feels different

Time to first token (TTFT) covers the wait before output begins, including prompt processing and potentially queueing and other overhead. Inter-token latency measures the gaps between subsequent output tokens. These are distinct measurements; a slow first token alone does not prove prefill is the bottleneck. Measurement source: vLLM.
