What the cache remembers

You already explained that decode processes one generated token while reusing results for the prompt. Now open that cache: what are those results, and how do they influence the next prediction?

1. Mix information from the sequence

Vector
A list of numbers. Inside the model, vectors represent information about tokens.
Attention
A calculation that mixes information from accessible tokens, giving each contribution a computed weight.
Weight
Here, a share of the mixture. The attention weights add up to 1, or 100%.

Consider [The][ cat][ sat], with invented token boundaries. While processing [ sat], attention can draw information from all three tokens, including itself. The result is another vector, not a selected word. Further model calculations produce next-token scores. Source: attention.

2. Match with keys, mix the values

Query (Q)
A vector used to calculate how strongly the current token matches each accessible key.
Key (K)
A token’s vector used for that matching calculation.
Value (V)
A token’s vector whose information contributes to the mixture.

The model creates Q, K, and V through learned numerical transformations of token representations. These are mathematical roles, not literal questions, dictionary keys, or stored words.

This weighted sum is the attention result. Source: queries, keys, and values.

3. Save the parts that remain useful

Causal attention
Attention restricted to the current token and earlier tokens; later tokens cannot influence earlier ones.
Key-value (KV) cache
Saved keys and values for already processed tokens, reused during generation.
Layer
One processing stage in the model. Each attention layer has its own cached keys and values.

Because later tokens cannot change earlier results, old keys and values remain valid. Each decode step computes the new token’s Q, K, and V, appends its K and V, then uses its Q with the accumulated keys and values. Old queries are not needed for this step. Source: cache reuse.

The cache avoids rebuilding old keys and values; attention still computes new matches and a new mixture. In this full-context example, storing another pair for every processed token makes the cache grow. Some architectures limit retained context; we are following the basic case. Source: per-step work.

Try a tiny mixture

For arithmetic only, replace each value vector with one number: The = 2, cat = 10, sat = 4. Keep these values fixed and change the weights. Predict whether the result will rise before pressing the second button.

The10%10%
cat60%60%
sat30%30%

0.10 × 2 + 0.60 × 10 + 0.30 × 4 = 7.4

The buttons supply invented weights directly; they do not simulate the query–key calculation. The experiment isolates mixing.

Explain the change

The second mixture is 0.10 × 2 + 0.20 × 10 + 0.70 × 4 = 5.0. It falls because weight moved from 10 toward 4. The stored values stayed fixed; different weights produced a different result.

One transfer check

A prompt contains three tokens. Prefill selects a fourth token, and decode processes it to select a fifth. At that moment, which tokens have cached keys and values? When processing the fifth token, what is reused and what must be calculated afresh?

Compare your explanation

The first four tokens have cached K,V pairs; the fifth has only been selected. Processing it creates its Q, K, and V and appends its K,V pair. Its query makes new matches against all five keys; new weights mix all five values. The first four pairs are reused unchanged.

Send your explanation or anything unclear to the agent. This checks whether the distinction between saved data and new attention work has landed.
